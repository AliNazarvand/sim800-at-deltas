# Architecture

## Overview

The project ships a static, compile-time database of SIMCom SIM800
Series modules together with ESP32-WROOM-32 integration scaffolding.
The database is header-only; all data lives in ROM/flash when linked
into a firmware image.

Starting with this revision the project is **data-driven**: the source of
truth is a set of YAML files under `data/`, and the C++ header
`include/simcom/simcom_database.hpp` is generated by
`tools/generate_cpp.py`. Hand-editing that header is forbidden.

## Layers

1. Types (`include/simcom/simcom_types.hpp`)
   Plain structs and enum classes describing hardware, feature flags and
   AT command variations. No functions that allocate, no data.

2. Database (`include/simcom/simcom_database.hpp`) - AUTO-GENERATED
   Three `inline constexpr` arrays: `MODULES`, `VERSION_DELTAS` and
   `CROSS_REFERENCES`. No allocation, no string handling.

3. API (`include/simcom/simcom_api.hpp`)
   `inline` lookup helpers and query/format helpers returning pointers
   into the database. No allocation, no exceptions.

4. Umbrella (`include/simcom/simcom.hpp`)
   Includes the three layers above; the only header user code needs.

## Data Pipeline (phases)

- Phase 1 - Types: enum classes and extended structs.
- Phase 2 - Data structures: `ATCommandVersionDelta`, `ModuleCrossReference`.
- Phase 3 - Code generation pipeline: `extract_pdf.py`, `generate_cpp.py`,
  `validate_yaml.py`, `enum_mappings.py`, `template.hpp.j2`,
  `schemas/*.json`, `requirements.txt`.
- Phase 4 - Advanced query API: `find_modules_*`, `compare_modules`,
  `module_to_json`.
- Phase 5 - Exporters: `export_json.py`, `export_csv.py`, `export_markdown.py`.
- Phase 6 - PDF cross-validation: `validate_against_pdf.py`.
- Phase 7 - Documentation.
- Phase 8 - Tests, `CMakeLists.txt`, `.gitattributes`.
- Phase 9 - Deterministic output rules.

## Extending

To add a new module:

1. Append a new entry to the YAML files in `data/` (modules, at_deltas,
   cross_references) in the same order.
2. Run `python tools/validate_yaml.py --strict`.
3. Run `python tools/generate_cpp.py` to regenerate
   `include/simcom/simcom_database.hpp`.
4. Update `EXPECTED_MODULES` in `tools/validate.py`.

No API change is required.

## Data Sources

- SIM800 Series_AT Command Manual_V1.01 / V1.10 / V1.12.
- Hardware Design datasheets for each supported module.

## Known Limitations

- `flash_kb == 0` marks modules whose flash size is not stated in the
  Hardware Design datasheet (SIM808, SIM800A, SIM800F, SIM800).
- `gpio_count`, `adc_count`, `pwm_count` count dedicated pins only;
  pins available through multiplexing are not included.
- `jamming_pin` uses the pin name from Chapter 21.6.
- New fields added in this revision are populated with default values
  (`0`, `false`, `""`, `nullptr`) until human developers fill them in
  from the PDFs.

## Determinism

- Key order in YAML is fixed (declaration order).
- `generate_cpp.py` output is byte-for-byte identical between runs.
- Line ending `\n`, indent 4 spaces, UTF-8 without BOM.
